# Adaptive Always-On and shared requests

Each enabled agent has one persisted heartbeat deadline. The LLM receives all active goals, complete user-authored permission text, issue checklists, recent reports and answered steering, then chooses `next_delay_seconds` and `scheduling_reason`. The service clamps integer delays to 300–14400 seconds; missing/invalid choices fall back to one hour. No active goals use a quiet four-hour check. Scheduling is persisted from the run’s completion; the existing exclusive worker lease, budgets, and restart reconciliation remain in force. New human input can move a deadline forward, respecting the five-minute floor.

Goals retain configured GitHub repositories, `always-on` and `agent:<name>` labels. In every client, edit **Allowed autonomously** and **Ask permission first**. Saving pauses the goal, invalidates outstanding work and submits a revision-bound issue mirror through the existing repository approval gate. The issue contains a marked `wee-autonomy-remit` block. External issue changes import permission text into a paused goal for human review; they never silently grant a running agent authority. Resume explicitly after reviewing edits.

A heartbeat can propose up to three bounded progress actions: private workspace notes, issue comments, or exact existing issue checkbox updates. A user-authored allowance must be cited verbatim; ambiguous authority requires approval. Ask-first text and explicit global ask/deny rules take precedence. Unsupported shell, browser, delegation, arbitrary code changes and deployment remain unavailable. Supported actions are executed through the existing audited action boundary. Reports/progress notes provide persistent memory and artifacts in isolated goal workspaces. Pending questions/actions block that goal while other goals remain eligible.

## Global inbox and origin relay

`GET /api/v1/autonomy/inbox` is account-authenticated and intentionally independent of selected agent. It returns this instance’s stable UUID, pending approvals and steering, plus durable peer snapshots. Every WebUI/native root subscribes even when agent settings are closed. macOS subscribes to both local and remote APIs and relays its local inbox to the remote hub, forwarding winning responses back to the origin. Peer replies display “awaiting origin” until validated/delivered. Offline snapshots retain requests and durable reply queues; they do not imply an offline origin can execute.

For a headless origin, configure environment variables `WEE_ALWAYS_ON_HUB_URL` and `WEE_ALWAYS_ON_HUB_TOKEN` with an authorized hub URL and bearer token. TLS verification remains enabled for headless relay: use a trusted certificate/CA. The relay runs independently of bounded model work. Existing account authentication covers peer publication and replies; configure only trusted instances of the same account. Each origin checks its own current fingerprint/revision and policy before executing; the hub does not execute or grant permanent rules. All clients allow approve-once/reject globally; permanent rules retain their exact-scope review in agent settings.

Routes: `GET /heartbeats`, `PUT /responsibilities/{id}/instructions`, `POST /steering/{id}/answer`, `POST /inbox/{origin}/{id}/decision`, `PUT /relay/{origin}`, `GET /relay/{origin}/decisions`, and `POST /relay/{origin}/decisions/{id}/ack`, under `/api/v1/autonomy`.

## iOS notifications

Foreground clients refresh every five seconds and immediately display a request badge. Suspended iOS devices can opt in to APNs alerts. Configure the server with `WEE_APNS_KEY_FILE` (outside the repo), `WEE_APNS_KEY_ID`, `WEE_APNS_TEAM_ID`, and `WEE_APNS_TOPIC` (app bundle identifier). Install HTTP/2 dependencies via the versioned API requirements. Use a signed iOS build and provisioning profile supporting Push Notifications; Debug uses development/sandbox, Release production. Alert bodies are generic; details remain in the authenticated inbox. Deliveries are durable, deduplicated per device/request revision, retried with bounded backoff and collapsed by APNs. Invalid device tokens are disabled. Delivery depends on Apple/network/user notification settings. No APNs private key is stored in repository files.

Registration: authenticated `PUT /inbox/devices/{device}` with token and `sandbox`/`production`; `DELETE` unregisters. The iOS settings button requests system notification permission and the app registers its token. An alert tap opens the global inbox. Live signed-device delivery needs QA with configured credentials; unsigned simulator builds and mocked transport tests do not establish it.
